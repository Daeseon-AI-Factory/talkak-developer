# Talkak Dev 제품 기본 동작과 가벼운 기억 — 최종 설계안

상태: 사용자 요청에 따른 구현 기준. 구현·출시·효과 검증 완료를 의미하지 않는다.

## 적용 대상

- 개인 맥북 설정이 아니라 설치 패키지에 포함되는 제품 기본 동작으로 제공한다.
- Windows와 macOS, 지원하는 각 에이전트에 같은 정책을 적용한다.
- 이번 설계와 후속 구현의 대상은 `talkak-dev`로 한정한다.
- 기존 `ddalkkak`는 필요한 구현을 참고하는 용도로만 사용한다. 해당 제품의 수정·재배포·전역 설정 정리는 이번 범위에 포함하지 않는다.

## 원하는 결과

프로젝트와 세션을 바꿔도 필요한 맥락을 이어가되, 기억 관리 때문에 입력·화면 전환이 느려지거나 에이전트가 일을 불필요하게 늘리지 않도록 한다.

우선순위는 입력과 터미널의 정상 동작, 세션 복구, 필요한 기억 전달이다. 기억 기능을 입력·포커스·스크롤 경로의 선행 조건으로 만들지 않는다.

## 제품 기본값

| 항목 | 설계 결정 |
| --- | --- |
| 정책의 원본 | 앱에 포함되는 짧은 공통 지침. 에이전트별 어댑터는 전달 방식만 담당한다. |
| 적용 범위 | 사용자가 구성한 앱 내부 에이전트 세션. 전역 설정·셸 프로필을 변경하지 않는다. |
| 기억 저장소 | 프로젝트별 로컬 저장소. 다른 프로젝트 기록은 자동으로 섞지 않는다. |
| 기억 연결 | 사용자가 호환되는 실행 프로필을 구성하면 새 세션에 기본 제공하고 화면에서 끌 수 있게 한다. 실행 파일 이름만으로 호환성을 추정하지 않는다. |
| 임의 CLI | 지원 계약이 확인되지 않은 실행 명령에는 인자를 임의로 추가하지 않는다. 기록 열람·복사 기능은 유지한다. |
| 기억 조회 | 이어서 작업할 때 선택한 인수인계를 읽고, 과거 맥락이 필요한 작업에서 추가 검색한다. 매 턴 조회하지 않는다. |
| 모델·추론 강도 | 사용자가 선택한 에이전트 설정을 존중한다. 제품에서 특정 모델이나 강도를 강제하지 않는다. |
| 기존 사용자 설정 | 명시적인 끄기·사용자 지침이 제품 기본값보다 우선한다. 알 수 없는 기존 설정을 지우지 않는다. |

기억 연결과 과도한 행동 지침을 하나의 스위치로 취급하지 않는다. 공통 지침에는 기록의 출처·범위와 필요한 작업 규칙만 둔다.

호환 연결에서 기억만 끄면 짧은 작업 지침은 유지하고 기억 저장소를 열거나 기억 도구를 제공하지 않는다. 직접 실행을 선택하면 앱의 지침과 도구 연결을 모두 생략한다. 연결은 사용자가 지정한 에이전트에만 적용하며, 기존의 연결 미지정 프로필을 실행 파일 이름으로 추측해 바꾸지 않는다.

### 시작 지침 전달과 확인 범위

MCP 초기화 지침만으로는 Codex의 첫 턴 수신을 확인하지 못했으므로, 명시적으로 선택한 연결 어댑터가 새 세션의 시작 인자로 공통 지침을 전달한다. 원본 정책은 두 어댑터가 공유한다.

- JSON 연결: 기존 `--append-system-prompt` 내용을 보존해 공통 지침과 합친다.
- TOML 연결: 설정·프로필을 적용한 `debug prompt-input`의 `generic.developer_instructions` 항목만 읽어 기존 사용자 지침을 보존하고 공통 지침과 합친다. 모델 호출이나 전역 설정 쓰기는 없다. 권한·스킬 등 내장 지침은 복제하지 않는다.
- 진단이 지원되지 않거나 기존 지침을 안전하게 구분하지 못하면 오류와 직접 실행 재시도를 제공한다. `--ignore-user-config`, `--remote`, `--worktree`, JSON 연결의 `--append-system-prompt-file` 같은 충돌하는 실행 방식은 추측해서 바꾸지 않는다.

2026-09-23 macOS 앱의 실제 실행 경로에서 Codex 0.155.1과 Claude가 공통 지침의 지정 문장과 기존 사용자 지침의 표식을 첫 응답으로 반환했다. 출력은 `CODEX_NATIVE_FIRST_TURN_OK: default policy and original user instruction received; exit=0`, `CLAUDE_NATIVE_FIRST_TURN_OK: default policy and original user instruction received; exit=0`, `2 passing (9.7s)`였다. Codex 출력에는 도구 호출 이벤트가 없었고 Claude 결과는 `num_turns: 1`이었다. 이는 시작 문맥 전달의 확인이며 모든 작업에서 준수하거나 토큰이 절감된다는 증명은 아니다.

Codex는 설치된 네이티브 실행 파일과 npm 실행기 모두 확인했다. 구성된 명령에는 앱의 PATH를 전달하되 사용자가 지정한 PATH가 우선한다. 시작 검사와 실제 세션·복구 실행이 이 값을 공유하며 기본 로그인 셸의 기존 동작은 유지한다.

최종 앱 시험은 현재 빌드의 전용 브로커를 사용했고 기억 UI 시험까지 `Spec Files: 2 passed, 2 total`을 반환했다. 앞선 설치본의 상주 브로커를 이용한 시험에서는 `env: node: No such file or directory`가 발생했다. 기존 브로커를 계속 사용하는 업데이트 경로까지 이 성공으로 증명하지 않는다. 시험용 접속 경로 분리는 `webdriver-ci` 빌드에만 포함되며 기존 실행 중인 사용자 세션을 종료해 브로커를 강제 교체하지 않는다. Windows 실기기·구버전 CLI·다른 설치 방식은 별도 확인 대상이다.

`session_context`는 지침과 선택 ID를 다시 읽어야 할 때 사용한다. 도구 설명에는 전체 지침을 중복하지 않는다. 기억을 껐을 때는 이 읽기 도구만 남기며 기억 본문이나 저장소에는 접근하지 않는다. 선택한 기억 본문은 `memory_read`로 조회할 때만 전달한다.

## 기억의 내용과 수명

기억은 기존 기록의 짧은 본문을 활용한다. 별도 분류 체계나 그래프 편집 화면을 새로 만들지 않는다.

- 결정과 이유: 무엇을 선택했고 어떤 조건 때문인지.
- 실패한 시도: 어떤 상황에서 무엇이 실패했는지.
- 인수인계: 남은 문제, 관련 파일, 다음 행동.
- 검증 근거: 실행한 명령과 결과의 위치, 실행 시점, 당시 코드·환경을 식별할 수 있는 정보. 식별할 수 없으면 그렇게 쓴다.

일상적인 진행 보고를 전부 기억으로 승격하지 않는다. 의미 있는 결과나 작업 인계가 생겼을 때 현재 작업 중인 에이전트가 짧은 기록을 남기도록 요청한다. 별도 요약 모델이나 백그라운드 에이전트를 실행하지 않는다.

에이전트가 기록을 남기지 않았다면 앱은 자동 저장·요약이 됐다고 표시하지 않는다. 사용자가 기존 응답을 바탕으로 인수인계를 작성·수정할 수 있어야 한다. 단순 발췌는 요약으로 표시하지 않는다.

기록에는 출처와 작성 시점을 보존한다. 정정은 기존 기록과 연결하고 검색에서 대체된 기록의 우선 노출을 피한다. 과거 기록은 현재 사실이나 실행 지시가 아니다.

## 읽고 이어가는 흐름

1. 프로젝트에서 작업하고 의미 있는 결과를 짧은 기록으로 저장한다.
2. 사용자가 이어갈 인수인계를 선택한다.
3. 새 에이전트 세션에는 선택 기록의 식별자를 전달한다. 전체 대화·전체 기억 본문을 시작 문맥에 넣지 않는다.
4. 에이전트는 해당 기록을 읽고, 필요한 경우에만 추가 검색한다.
5. 관련 기록이 없거나 오래됐다면 현재 소스에서 확인하며, 기억을 채우기 위한 추측을 저장하지 않는다.

앱 복귀·탭 전환·키 입력은 기억 검색이나 요약 생성의 트리거가 아니다. 기억 연결 실패가 터미널 사용을 막지 않도록, 실패를 표시하고 기억 없이 세션을 시작할 경로를 제공한다. 읽던 세션을 몰래 재시작하지 않는다.

실행 시작 오류 또는 실패 코드로 종료된 실행에는 같은 명령을 앱 연결 없이 다시 실행할 버튼을 제공한다. 자동 재시도하지 않으며, 이 선택은 프로젝트 기본값을 바꾸지 않는다.

## 공통 작업 지침의 내용

아래 내용은 제품에 넣을 제안이며, 현재 세션의 상위 지침을 바꾸지 않는다.

> 요청한 결과를 충족하는 작은 변경을 우선한다. 질문과 조사를 구현 작업으로 확대하지 않는다.
> 미래의 가상 요구를 위한 기능·설정·추상화를 추가하지 않는다.
> 과거 결정이나 미완료 작업이 필요할 때 기억을 조회하고, 이미 읽은 변경 없는 기록을 반복해서 읽지 않는다.
> 변경의 영향과 저장소 규칙에 맞는 검사를 실행한다. 관련 변경·실패·새 의문이 생기지 않았다면 통과한 검사를 반복하지 않는다.
> 과거 검사 결과는 당시 근거로 인용한다. 현재 상태를 증명하는 데 부족하면 필요한 부분을 확인하고, 확인하지 않은 부분을 명시한다.
> 필요한 결과와 검증을 갖추면 작업을 마친다. 추가 개선은 실제 문제의 근거가 있을 때만 제안한다.
> 의미 있는 결과나 인계가 생겼을 때 출처가 있는 짧은 기록을 남긴다.

저장소가 요구하는 검사와 출시 관문은 유지한다. 상위 지침과 충돌한다면 출처를 밝히고 그 지침을 정리해야 한다. 하위 지침을 겹쳐 넣어 해결된 것으로 처리하지 않는다.

## 검증 결과의 재사용

별도 검사 캐시·자동 검증 엔진을 만들지 않는다. 기존 명령 출력과 기록을 근거로 사용한다.

- 같은 작업에서 관련 입력·코드·의존성·환경이 그대로라면 이미 실행한 검사를 근거로 삼을 수 있다.
- 현재 상태를 판단해야 하는데 동일성을 확인할 수 없거나 관련 변경이 있었다면 필요한 검사를 실행한다.
- 외부 서비스 상태와 간헐적 PTY 증상은 과거 성공만으로 현재 성공을 보장하지 않는다.
- 기록된 결과와 이번 실행 결과를 구분해서 표시한다. 에이전트의 성공 선언은 검사를 대신하지 않는다.

## 설치와 업데이트

배포 패키지에 공통 정책과 로컬 기억 런타임을 포함한다. 개발 저장소의 위치, 개인 설정 파일, 수동 설치 스크립트에 의존하지 않는다.

새 설치와 업데이트는 같은 제품 기본 정책을 사용한다. 다만 사용자가 명시한 설정은 유지한다. 이미 실행 중인 에이전트의 문맥이 업데이트로 바뀌었다고 표시하지 않고, 새 정책은 이후 시작하는 세션에 적용한다.

업데이트 정리는 `talkak-dev`가 실제로 생성했던 설정이 있을 때만 필요하다. 앱 소유임을 식별하고 백업한 항목만 변경한다. 소유 여부가 불명확한 전역 지침·훅·MCP 설정은 자동 삭제하지 않는다. 기존 `ddalkkak`의 전역 설정을 정리하는 기능은 추가하지 않는다.

Windows와 macOS에서 새 사용자 설치와 기존 설정이 있는 업데이트를 각각 확인한다. 개인 맥북용 복구 스크립트를 제품 업데이트 경로로 재사용하지 않는다.

## 한도와 성능에 관한 약속

기존 구현의 크기 제한을 출발점으로 유지한다. 아래 수치는 이번 설계에서 새로 요구한 정확한 토큰 수가 아니다.

| 항목 | 값 | 분류·근거 |
| --- | --- | --- |
| 기억 제목 | 120 Unicode scalar values | MAX, `session-broker/src/memory/mod.rs` |
| 기억 본문 | 1600 Unicode scalar values | MAX, 같은 파일 |
| 완성된 기억 도구 응답 | 8192 UTF-8 bytes | MAX, 같은 파일; 모델 토큰 수와 다름 |

개별 응답 제한이 세션 전체 토큰 사용량을 제한한다고 주장하지 않는다. 반복 조회 감소는 작업 지침이며 모델이 준수했는지는 실제 실행으로 확인한다. 앱은 프로젝트 격리·응답 크기·설정 적용 범위를 제어하고, 에이전트의 모든 도구 호출을 통제한다고 약속하지 않는다.

시간·토큰 절감 비율은 미정이다. 현재 정책과 후보 정책으로 같은 작업을 수행해 결과의 정확성, 반복 검사, 문맥 전달량, 소요 시간을 비교한다. 토큰 사용량을 읽을 수 없는 실행은 토큰 절감 근거로 삼지 않는다.

## 완료 판단

- 새 설치에서 지원 실행 프로필로 기억을 저장·조회·인계하고 앱 재시작 후 다시 읽을 수 있다.
- 업데이트 후 명시적인 사용자 설정과 기록이 유지되고, 확인된 앱 소유의 낡은 설정만 처리된다.
- Codex와 Claude의 실제 실행에서 같은 기록을 읽을 수 있다. 다른 에이전트도 지원 계약을 만족하면 같은 저장소·정책을 사용한다.
- 평범한 수정 작업에서 기억 조회와 검사가 불필요하게 반복되는지 관찰하고, 정확성이 떨어졌다면 후보 정책을 다시 조정한다.
- Windows와 macOS에서 한글 입력, 페이지 전환, 앱 복귀, 출력 중 세션 전환을 확인한다. 기억 작업은 이러한 조작을 막지 않는다.
- 수행하지 않은 플랫폼·설치 경로·실제 에이전트 검증을 명시한다. 공통 코드 검사만으로 제품 완료를 선언하지 않는다.

위 항목은 출시 후보에 대한 판단 기준이다. 일상적인 작은 수정마다 전체 절차를 반복하라는 지침이 아니다. 이 문서 작성만으로 해당 항목이 통과한 것은 아니다.

## 이번에 읽은 근거

제품 기본 지침의 원본은 `session-broker/src/memory/session-policy.txt`이며 브로커와 앱에 컴파일한다. `memoryEnabled: false`는 사용자가 끈 선택을 보존한다. 실제 전달은 세션 시작 어댑터와 MCP 초기화·`session_context` 경로를 사용한다. 이 지침은 모델이 참고하는 작업 규칙이며 앱이 모든 행동을 강제하는 기능은 아니다.

- `AGENTS.md`: 작은 개발자 워크스페이스, 에이전트 중립, 두 플랫폼 지원, 전역 설정 변경 금지.
- `src/runtime/memoryClient.ts`: 현재 인수인계 초안은 발췌 방식.
- `session-broker/src/memory/{mod,mcp}.rs`: 프로젝트 범위, 크기 제한, 필요할 때 조회하는 지침과 선택 ID 전달.
- `src-tauri/src/memory_commands.rs`, `src-tauri/src/session_commands.rs`: 명시적으로 선택한 연결 어댑터와 세션 실행 인자.
- `src-tauri/src/session_policy.rs`: 기존 사용자 지침을 보존하는 시작 인자 구성. TOML 진단은 출력 4 MiB, 대기 8초가 MAX이며 입력·포커스·페이지 전환 시 실행하지 않는다.
- 운영 기억 `startup-msut9yuz-9xb4/flow/intent-d6710c53570a626a`: 프로젝트별 기억, 전달량 제한, 개인 설정·개발 저장소에 의존하지 않는다는 기존 의도. 과거 의도 기록이며 구현 증명은 아니다.
- 운영 기억 `startup-msut9yuz-9xb4/work_item/agent-715ed1947f0ca995`: 제품 기본값과 기존 설치 전환의 후속 검토. 이 문서의 결정이나 완료를 대신하지 않는다.
